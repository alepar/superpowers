| stash-tar.1 | 1 | — | Add `tar` backend (save, list, check) with per-backend configuration smoke | Add `tar` as a third backend alongside `dir` and `zip`, following the existing per-backend branches. `config.SUPPORTED` gains `"tar"`. `config.snapshot_suffix("tar")` returns `".tar.gz"`. `commands.save` writes a gzip-compressed tar (`tarfile`, mode `"w:gz"`) of the source tree with member names relative to the source. `commands.list_snapshots` lists `*.tar.gz` entries in dest. `commands.check` reports `tar` usable when gzip support (`zlib`) is importable. `report.label("tar")` returns `"tar archive"`. It is the only leaf, so it has no sibling boundaries and no owns:/consumes: lines. Notes: no seam was admitted. The only candidate was a backend interface or registry, class N, since five call sites already branch on the backend kind. Its obligation fails on the direct check: adding a `tar` branch at each site and testing every command under `tar` meets and checks the requirement without it. Planned remote backends are a likely future change, which does not justify a seam, and D1 forbids moving labels into backends. The change is small and its files are tightly coupled, so it falls below the split floor and stays one leaf. The root integration sweep is not part of this step.
