# Decomposition: Show snapshot age in `stash list`

| id | depth | deps | title | short description | files-touched hint | acceptance criteria |
|---|---|---|---|---|---|---|
| snapshot-age.1 | 1 | — | Show snapshot age in `stash list` | Add an age formatter that parses the leading `%Y%m%d-%H%M%S` timestamp (local time) from a snapshot name, ignoring any backend suffix such as `.zip`, and formats its age against a supplied current time as `Nd Hh` (days and hours, e.g. `2d 3h`, `2d 0h`), `Hh` when under a day, or `<1h` when under an hour. A timestamp in the future also prints `<1h`. `list_snapshots` reads the current local time once and prints each name followed by two spaces and its age (`20261120-101500  2d 3h`), for both the `dir` and `zip` backends. A name whose prefix does not parse as a timestamp prints unchanged, with no age, and does not crash the listing. Sort order and the empty-listing message stay as they are. Add the project's first tests using stdlib `unittest`, since the repo has no test setup and no third-party dependencies. | `stash/commands.py` (`list_snapshots`, plus the formatter here or in a small helper module); `tests/test_age.py` (new) | - [ ] `stash list --backend dir --dest D` prints each snapshot as `<name>  <age>`, with the age computed from the name and the current time (R1)<br>- [ ] `stash list --backend zip --dest D` does the same for `*.zip` names, and the `.zip` suffix does not break timestamp parsing (R1)<br>- [ ] Tests pass a fixed current time to the formatter (they do not read the wall clock) and cover `<1h` (e.g. 59 minutes old), hours-only (e.g. 5h), and multi-day (e.g. `2d 3h`) (R2)<br>- [ ] One test runs `list_snapshots` on a temp dest holding a snapshot created relative to a pinned current time, and its result does not depend on the day it runs (R2)<br>- [ ] A name with no parseable timestamp prefix is listed unchanged and the command still exits 0<br>- [ ] Sort order and the empty-backend message are unchanged<br>- [ ] `python -m unittest discover -s tests` passes |
