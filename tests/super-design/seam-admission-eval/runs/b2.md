# Decomposition: Add `--limit` to `stash list`

Epic slug: `stash-list-limit`. Root spec: `inputs/spec.md`.

| id | depth | deps | title | description | files-touched hint | acceptance criteria |
|---|---|---|---|---|---|---|
| stash-list-limit.1 | 1 | — | Add `--limit N` to `stash list` | Add an optional `--limit N` argument to the `list` subparser and pass it to `commands.list_snapshots`, which prints only the last N names of the already-sorted list (the newest, because names start with their timestamp). When the flag is absent, the output does not change, the empty-store message included. The flag is parsed as an int, and a value below 1 is rejected with an argparse error. `save` and `check` stay as they are. The CLI flag and its consumer are tightly coupled, and one implementer lands both in one change, so there is no sibling and no owns:/consumes: line. | `stash/__main__.py`, `stash/commands.py`, new `tests/test_list_limit.py` | <ul><li>- [ ] `stash list --backend dir --dest D --limit 2` with 3 or more snapshots in D prints exactly the 2 newest names, oldest first, the same order as the unlimited output</li><li>- [ ] the same holds for `--backend zip`</li><li>- [ ] `--limit N` with N greater than or equal to the number of snapshots prints every snapshot</li><li>- [ ] without `--limit`, the output for a populated store and for an empty store is byte-identical to the pre-change output</li><li>- [ ] `--limit` on an empty store still prints the existing "no ... stored" message</li><li>- [ ] `--limit 0`, a negative value and a non-integer value each exit non-zero with an argparse usage error</li><li>- [ ] `save` and `check` have unchanged arguments and behavior (their `--help` output is unchanged)</li><li>- [ ] the new tests pass, and so does every existing check</li></ul> |

Decisions recorded at decomposition:

- **One leaf.** The change touches about ten lines in two tightly coupled files. Splitting the CLI flag from its handling would cost more ceremony than the implementation itself and would turn a single function call into a seam between siblings.
- **No seam admitted.** Class P does not apply because there are no parallel siblings. Class V does not apply because the check runs against a temp directory, and the real filesystem is deterministic enough. Class N does not apply: the limit is applied after the backend-specific listing, so this change does not touch the existing `if backend ==` branches in `config.py`, `report.py` and `commands.py`. A backend abstraction would be a refactor nobody asked for.
- **No `Configuration smoke:` row.** The spec does not enumerate runtime configurations. The existing `dir` and `zip` backends are already covered by the leaf's acceptance criteria.
- **No deletion and no hot-file split.** The leaf has no blocking edges and so no `blocked-by` lines. The root `Integration sweep:` row belongs to §Coverage after its loop ends, so it is not created here.
