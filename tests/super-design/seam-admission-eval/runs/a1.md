# Decomposition: Add a `tar` backend to stash

Root epic: `stash-tar` (no-beads mode). Root spec: `inputs/spec.md`.

| id | depth | deps | title | description | files-touched | acceptance |
|---|---|---|---|---|---|---|
| stash-tar.1 | 1 | — | Add `tar` backend (gzip-compressed `.tar.gz` snapshots) | Add `tar` as a third backend next to `dir` and `zip`, using the existing inline per-backend branches: accept `tar` in `config.SUPPORTED`; `config.snapshot_suffix("tar")` returns `.tar.gz`; `commands.save` writes a gzip tar (`tarfile.open(target, "w:gz")`) holding the source tree with paths relative to `source`; `commands.list_snapshots` lists entries ending in `.tar.gz`; `commands.check` reports `tar` usable when gzip support (`zlib`) imports, else unavailable; `report.label("tar")` returns `"tar archive"`. ## Notes

- One leaf. The change is one feature in one subsystem: `config.py`, `commands.py` and
  `report.py` are coupled by the backend-name branches, and splitting them would only move that
  coupling into a seam two implementers must agree on. Each piece alone is smaller than a bead's
  ceremony.
- No seam admitted. The existing call sites already branch on backend (`config.SUPPORTED`,
  `config.snapshot_suffix`, `commands.save`, `commands.list_snapshots`, `commands.check`,
  `report.label`), which could qualify as class N, but the direct check works: add one inline
  `tar` branch per site, and the per-command tests plus the three-backend smoke catch a missed
  branch (for example `snapshot_suffix` returning `None`, or `label` printing `None`). Planned
  remote backends are a likely future change, not a reason for a seam. A backend interface that
  owned labels would also conflict with D1.
- The configuration smoke runs inside stash-tar.1 rather than as its own row. That bead is the
  only one, so absorbing the smoke adds no bottleneck.
