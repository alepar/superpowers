# Review continuity followups — Design

Run: `docs/superpowers/runs/2026-10-28-review-continuity-followups/` · Beads: super-plan-2s3, super-plan-rsc, super-plan-tco, super-plan-row, super-plan-v94, super-plan-1s3, super-plan-zhk

## Goal

The seven open P1/P2 followups from the Herdr mosh Phase 1/2 triage are fixed in the existing scripts, prompts and tests: generated review reports extract completely or fail loudly, review provenance is scoped to the captured range, canonical roast callers carry evidence-backed review readiness, missing finding bookkeeping is visible, reused stacked task workspaces are reconciled with current prerequisites without losing work, both context-window resolvers agree, and project commit policy reaches the commit step and is graded as a requirement.

Literal human request: "lets $ht handoff to claude-2 all p1 and p2 fixes, at once, using /super-auto in fully autonomous mode, both roasts on". Everything below that goes beyond naming the seven issues is this design's elaboration, sourced to each bead's acceptance text.

## 1. Problem description

Two Herdr runs (mosh Phase 1 at alepar/herdr@be183064, Phase 2 at @a900f967) produced seven triaged defects in Superpowers 6.4.2-alepar6.6. Investigation of each (scratchpad findings `inv-*.md`, summarized here) confirmed every code gap: (2s3) `report-verdict --complete` strictly parses every recognized section anywhere in a report, while producer prompts constrain only the closing footer, so narrative `## Findings` sections, prose preambles and sub-headings make extraction fail (exit 2) — and a sub-heading inside a recognized section silently drops the items under it with exit 0; (rsc) `dispatch-text review-inputs` snapshots and validates every `run.md` in the tree at both endpoints, so one untouched old run with an incomplete collection blocks a product-only range; (tco) super-roast requires `reviewReadiness` to converge, but its Inputs table does not list it and no canonical caller passes it, so no canonical roast loop can reach `[converged]`; (row) callers wrote zero `finding-route`/`finding-link`/`finding-disposition` records and nothing detected it — the projection silently returned nothing deferred, and pending human escalations exist only as free-text `parked:` lines; (v94) coordinator workspaceSetup reuses an existing task branch+worktree with no stack step or ancestry check, and has no case at all for branch-only or worktree-only; (1s3) `context-preflight` falls through to 200K for every explicit id that lacks `[1m]`, while `context-pass.mjs`'s documented table gives Opus 5 / Sonnet 5 / Haiku 5.5 / Fable 1M; (zhk) the implementer prompt's Commit step says nothing about message policy, Claude Code loads `CLAUDE.md` not `AGENTS.md`, the harness attribution reminder asks for trailers, and the task-review rubric files a constraint violation under style/Minor while its review package shows commit subjects only.

## 2. Main challenges

Each fix must close the confirmed gap without erasing the guard that caused it: extraction must not start ignoring narrative findings; provenance scoping must not waive inherited gaps that a broad range really contains or filter by run id; readiness must never be synthesized as complete; bookkeeping detection must make omissions visible without inferring resolution from display keys, bead closure or later clean reviews; workspace reconciliation must never reset, delete or WIP-commit task work; the window fix must not invent knowledge for bare aliases; the commit-policy fix must not become a hardcoded trailer ban. Two historical causes stay qualified (exact mosh-hex.5 setup failure; exact commit-producing agent), and the fixes target the verified code gaps only. Skill-text edits must be small and evidence-led (project rule: writing-skills plus behavior evidence), and a separate tab owns super-auto default-flag changes in shared sections.

## 3. Key decisions made

Align producers to the existing extractor grammar and tighten the extractor where it silently loses items, rather than relaxing it. Producers self-check with `report-verdict --complete` and the roast orchestrator re-dispatches the reporter once with the parser error, only on the extractor's distinct grammar-failure exit, and accepts the repair only when a mechanical `report-verdict --repair-check` finds its header and keys equal to the original's and every original line kept in place, changed at most by an added list marker; originals are never overwritten. Provenance relevance is a path-only rule on the captured changed-path inventory. Readiness is derived from the assembler's `review-inputs.json` (code roast) or from committed spec identity (design roast), else `unknown`. Missing bookkeeping becomes explicit projection gaps in the existing `scope-dispositions --project`; pending human escalations use a `finding-route` with a reserved `deferred` reason prefix — no new record kind. Workspace reuse reconciles by rebase of the task's own commits onto a rebuilt stack base only when the worktree is clean, else fails typed with everything preserved. `context-preflight` gets a bash mirror of `CLAUDE_WINDOWS` with a parity test. Commit policy is stated in the implementer's Commit step and graded as Important in task review, with full commit messages in the review evidence.

## 4. Decision points, by section

### 4.1 Report format contract (super-plan-2s3)

**Recommended:** (a) Rewrite `reviewFileFormat()` in `skills/super-code/coordinator.js` (~L2992) to state the whole-file rule: the recognized section words (`findings`, `must fix`, `concerns`, `blockers`, `deferred`, `untested scope`) mark extractable sections anywhere in the file, so narrative analysis goes under headings that do not use those words; each recognized section holds only `- ` items (indented continuation lines allowed) or the single item `- none`; no sub-headings, bold labels or prose preamble inside one. (b) Give every section of the super-roast reporter template (`skills/super-roast/reporter-prompt.md` Step 6 and the mirror in `skills/super-roast/SKILL.md`) the same body rule, including Rejected, Unverified nits and Escalations. (c) Validation (the `--complete` contract, stated once here and cited by §4.4): `report-verdict --complete` gains a distinct grammar-failure exit — **exit 4** when the file was read and decoded but its content fails the grammar (unrecognized finding source, missing verdict, missing or empty finding section, unmarked text, a forbidden sub-heading per (d)); exit 2 stays reserved for usage errors, an invalid source id and an unreadable, non-file or invalid-UTF-8 artifact. The stderr prefix `report-verdict: --complete: ` is unchanged, and existing callers already treat any nonzero status as failure. Validation runs discard the JSON and use the fixed source id `format-check`. Final/cluster/seam reviewers run `bash ${codeSkill}/scripts/report-verdict --complete --source format-check <their file>` (the coordinator's `codeSkill` path) before returning and, only on exit 4, fix the formatting it reports (finding content unchanged); any other nonzero exit is noted in their report, not repaired. The roast orchestrator, after writing `reportMarkdown`, runs the same command on the written file and only on exit 4 re-dispatches the reporter once with the parser error and the original path, writing the repaired report to a new sibling file (`…-format-repair.md`). Header-only failures (`unrecognized finding source`, `missing verdict value`) are not re-dispatched, since check (ii) below can never pass for them: the original is recorded and the friction line names the error. Acceptance is one mechanical command, a new mode in the same script: `report-verdict --repair-check <original> <repair>` exits 0 to accept, 4 to reject with `report-verdict: --repair-check: <failed check>` on stderr, and 2 for usage or I/O errors (treated as reject). It accepts only when (i) the repair passes `--complete`; (ii) every line before the first `## ` heading (verdict and qualifier lines) is byte-identical; (iii) `--keys` output is identical for both files; and (iv) line alignment: after deleting blank lines and `- none` lines from both files, the two files have the same number of lines and each repair line equals the original line at the same position, or is that line prefixed with `- ` (the original line was not already a list item), or — only where the original line is a heading deeper than `## ` or a bold label whose label is not a recognized roast section word — is `- <that label>`. Lines inside a fenced block (per (d)) compare as plain lines. So the repair can only add list markers and `- none`, demote a forbidden sub-heading to an item, and drop blank lines; it cannot drop, reword, reorder or relocate a line, add or rename a section heading, or move a continuation line, and every original line keeps its section because no section boundary changes. A shape that needs any other edit (e.g. a missing recognized section) is rejected loudly rather than checked weakly. An accepted repair is the round's report path; the original stays on disk beside it and the orchestrator appends `report format repair: <original> → <repair> — <parser error>` to the friction log. When the repair is rejected, the original is the round's report path, the friction line names the failed check, and collection's existing `complete extraction unavailable` gap stands; the finding content is never edited by the orchestrator. *Round's report path* is defined once, in super-roast's report write step (`skills/super-roast/SKILL.md` ~L218-220): the path that step ends on (accepted repair, else original); the orchestrator that runs that step is the caller's own session, which then records it. Each caller site that records or passes a roast report states that it uses this path: super-auto's phase-4 row write sentence ("Once super-roast returns `reportMarkdown`, write it to the round's report file …", which the post-cap audit and the amend design roast also follow) for `roast-code:`/`roast-design:` and the next round's prior report, and super-design's §Adversarial Review Loop invocation paragraph and its run-state write table row (the `roast-design` report/input list). The round's report path is the only artifact later extraction reads: super-auto's `finding-source` for the round is `report-verdict --complete --source roast-design/round-N` (or `roast-code/round-N`, the existing convention in `super-auto/SKILL.md` §Review collection) run on that recorded path, so the record's `artifact` equals it. Work splits into two leaves: super-code producer prompts (a, c for final/cluster/seam) and super-roast reporter body rule plus format repair (b, c for roast, including `--repair-check` and the caller sentences named above). (d) Tighten the extractor: in `report-verdict --complete` and the copied grammar in `assembly-archive.cjs`, a sub-heading or bold-label line encountered inside a recognized section that already has items is an error (exit 4 in `report-verdict`; a thrown grammar error in `strictDraft`), not a section end. The discriminator, applied to a line the existing `heading()` regex matches (`^#+[ \t]+` or `^\*\*[^*]+\*\*`) inside a recognized section that has items: a line whose label is itself a recognized section label (that copy's own word list, any level, ATX or bold) is a sibling and starts the next section; an ATX heading at the same or a shallower level than the heading that opened the section is a sibling (recognized or not, e.g. `## Analysis` after `## Findings`); any other line — an ATX heading deeper than the opening level, or an unrecognized bold label — is the forbidden sub-heading. A section opened by a bold label is ended by any ATX heading or recognized bold label; an unrecognized bold label inside it is forbidden. In both copies, a line inside a fenced code block (from a line starting, after at most three spaces, with ```` ``` ```` or `~~~` to the next such line) is never a heading; it is ordinary item or continuation text. **Considered:** relaxing the extractor to accept narrative inside recognized sections — discarded, the issue forbids ignoring narrative findings and it would make keys ambiguous; a mechanical post-dispatch repair with report-status pairing — deferred as a follow-up if self-checks prove unreliable, it needs report-status changes.

### 4.2 Range-scoped review provenance (super-plan-rsc)

**Recommended:** In `reviewInputs()` in `skills/super-code/scripts/dispatch-text.mjs`, compute relevance per `run.md` after the changed-path list: relevant iff it is the caller-bound current run, or the run.md path itself, its `run.md.collection-origin.json` sidecar, or any path at or under `dirname(run)/reviews/` is in the captured changed paths, or it is re-read as a mirror origin (strict as today). Relevant runs keep every existing guard (parse problems, incomplete claimed collections, origin authentication). Irrelevant runs are still parsed (the mirror ambiguity check sees all runs) but their problems go to a new non-blocking `outOfRange` list in `review-inputs.json` and the provenance digest, labelled informational, neither selected nor waived; they never change the exit code. Evaluation order: snapshot and origin authentication emit run-attributed problems before mirror-origin status is known (`snapshot` at both endpoints, then `authenticateOrigins`, which re-reads origin runs through `validateCollections`), so the sink buffers each run-attributed problem with its run and classifies the whole buffer once, after `authenticateOrigins` has run at both endpoints and before `validateCollections` of the endpoints; problems emitted after that point are classified immediately. A run named as the origin of a mirror declaration that `authenticateOrigins` examined counts as re-read, whether or not the declaration authenticated, only when the mirror run that declares it is itself relevant by the path criteria above (a mirror can never be the current run); an untouched mirror/origin pair is therefore out of range, and its problems, including the declaration's own authentication gap, go to `outOfRange`. The mirror ambiguity check still runs over all parsed runs. One clause in `skills/super-auto/SKILL.md` §Review collection states the range scoping. A broad range (e.g. a final review from an older upstream base) includes the old run.md as a changed path, so its inherited gaps still block. **Considered:** filter by current run id — discarded, forbidden and wrong for broad ranges; parse claims to decide relevance — discarded, fails on corrupt run.md, while the path rule is a superset of any claim.

### 4.3 Review readiness at canonical callers (super-plan-tco)

**Recommended:** Add a `reviewReadiness` row to super-roast's Inputs table (`skills/super-roast/SKILL.md`) with its fields (`coverage`, `provenance`, `basis`) and its meaning. In super-auto phase 4 (each round and the `post-cap audit`), derive it from the round's assembler result: assembler exit 0 and `<dir>/review-inputs.json` with `status: complete`, no gaps, and base/head equal to the captured SHAs → `complete`/`available` with a basis naming that file, its status and the captured range; the typed `provenance unavailable; captured source available` bounded review → `bounded`/`unavailable` with the cause and inspected/unreviewed scope; any other assembler failure or direct fallback → `unknown`/`unavailable` with the cause. `fits` never changes readiness; readiness is never copied from a prior round nor inferred from a green sweep. Design roasts (super-design §Adversarial Review Loop and super-auto's amend design roast): `complete`/`available` only when every settled spec path is passed and committed clean at a captured HEAD SHA, with the SHA and path list as basis; otherwise `unknown`. **Considered:** always `unknown` for design roasts — discarded, it keeps design loops unable to converge although the artifact is fully captured; coverage-loop pass as basis — discarded, coverage judges the tree, not what the roast read. This design-mode basis is an agent decision and is parked for the human at hand-back.

### 4.4 Finding bookkeeping visibility (super-plan-row)

**Recommended:** In `skills/super-auto/scripts/scope-dispositions --project`, add the explicit gap `scope-filter decision without finding-route: round <N> <key>` for each recorded `scopeFilter-round-<N>` decision with no `finding-route` on a matching roast occurrence (key used only to detect missing bookkeeping, never to link or resolve), plus an additive `unrouted` metric. A declared report with no `finding-source` gets no second check here: `report-status --acceptance` (run by the default status mode) already emits `source coverage: declared report has no retained source extraction: <path>` for each plain declared `roast-code`/`roast-design` input, after exempting keys-only inputs and inputs covered by a `source-correspondence` record, and that is the check this design relies on for missing sources. A *matching roast occurrence* is a `finding-source` occurrence from the same round's roast source — the existing immutable id `roast-design/round-N` / `roast-code/round-N` (`super-auto/SKILL.md` §Review collection) — whose extracted key equals the recorded scope-filter key; that source's `artifact` is the recorded report path per the §4.1(c) `--complete` contract (the accepted `…-format-repair.md`, else the original), and a source whose artifact is not a recorded `roast-code:`/`roast-design:` path does not count as a matching roast source; the decision has a route when some `finding-route` names one of those occurrences' refs. The key equality only locates where a record should exist; it never creates a link, route or disposition. Gaps flow through existing exit-3 handling. Instruction fixes in `skills/super-auto/SKILL.md`: Step 2 appends the round's `finding-source` then one `finding-route` per scope decision, and on extraction failure records the gap and never substitutes scope keys for the punch list; Step 3 appends `fix:<bead>` routes; human-gated items (roast Escalations, reserved human decisions) get a `finding-route` with `deferred: "pending human decision: <what>"` carrying the occurrence ref, and the `parked:` line cites that ref; a later occurrence of a pending item is linked only by an explicit `finding-link` whose basis cites the evidence that it is the same defect (the later report's text, not its key); with no such basis it stays a separate occurrence; resolution only via a `finding-disposition` citing the human's recorded approval line. One sentence in `run-state.md` defines the reserved `pending human decision:` prefix. Bead closure, equal display key or a later clean review never dispose; autonomous mode never writes a human approval. Work splits into two leaves: the projector pass in `scope-dispositions` and the caller instructions in `super-auto/SKILL.md` and `run-state.md`. **Considered:** a new escalation record kind — discarded, the existing route `deferred` reason carries it; auto-linking by display key — forbidden.

### 4.5 Reused stacked workspace reconciliation (super-plan-v94)

**Recommended:** Change the workspaceSetup text the coordinator builds (`skills/super-code/coordinator.js` ~L2624-2645, used by both Workflow and ordinary-subagent mode via `dispatch-text.mjs`) so the both-exist ordinary-attempt path first checks drift: some current parent `task-p` is not an ancestor of the task branch (`git merge-base --is-ancestor`), or the branch carries a first-parent `stack: X` commit for an X no longer a current parent. No drift → reuse as today. Drift with a dirty worktree (ignoring `.tmp/`) → `SETUP_FAILED: prerequisite drift; uncommitted work preserved; nothing reset`. Drift with a clean worktree → record old head and old base, where old base is the existing both-exist base rule (the newest first-parent `stack:` commit on the task branch, else `git merge-base <branch> <integration>`), the same base the reviewer diff already uses; on a detached HEAD at the integration branch merge each current parent as `stack: p`, giving the new base; `git rebase --onto <newBase> <oldBase> <branch>`; on any conflict abort, restore the branch to the old head, and return `SETUP_FAILED` naming the old head (never the STACK_CONFLICT `--discard` path). Branch-only or worktree-only states, on both the ordinary-attempt and the review re-entry path: branch-only first runs the ALREADY-MERGED CHECK (a landed task whose worktree was removed with `--keep-branch` is branch-only) and returns ALREADY_MERGED when it prints true; otherwise, and always for worktree-only (no branch to check), return a typed `SETUP_FAILED` naming which exists, preserving both. The recut path is unaffected (its removal step runs first). No `-D`, `--force`, reset, WIP commit or stash. Docs in `coordinator-workflow.md` and `coordinator-subagents.md` follow. The resumed-`cancelled` recut seeding gap is out of scope (not requested); noted as a follow-up. The exact mosh-hex.5 failure cause remains qualified in the report. **Considered:** merging the new parent on top of the task's commits — discarded, it moves base above the task's own commits and the merge-time `rebase --onto` would drop them; resetting the branch to a fresh cut — forbidden.

### 4.6 Consistent model-window resolution (super-plan-1s3)

**Recommended:** Add a bash function `claude_window` to `skills/super-code/scripts/context-preflight` mirroring `CLAUDE_WINDOWS` in `context-pass.mjs` (ERE, case-insensitive `[1m]`), used by the explicit-id fallthrough and the same-family alias branch; keep the bare-alias-without-settings `unknown` case, env precedence, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and `--context-window` override unchanged; cross-reference comments in both files and `skills/super-code/MAINTENANCE.md`. A parity test runs ids through both resolvers and requires equal windows; its list has at least one matching and one boundary non-matching id per `CLAUDE_WINDOWS` row (e.g. `claude-opus-5` / `claude-opus-50`), and it asserts that the row count of `CLAUDE_WINDOWS` equals the number of `claude_window` patterns, so a row added to one table alone fails the test. **Considered:** calling node from context-preflight — discarded, it is deliberately bash-only; a shared JSON table read by both — more moving parts than a mirrored table guarded by a parity test.

### 4.7 Project commit policy at commit and review (super-plan-zhk)

**Recommended:** In `skills/super-code/implementer-prompt.md` "## Commit", add: commit messages follow the commit rules in the repository's instruction files (AGENTS.md, CLAUDE.md, CONTRIBUTING) and the brief's Global Constraints, and where those conflict with a harness's default attribution or trailer instruction, the project rule wins (fix passes inherit this step). In `skills/super-code/task-reviewer-prompt.md` severity rules, a violation of an explicit project or brief constraint — commit-message policy included — is Important (a missed requirement), not style; the reviewer inspects full commit messages (`git log --format=%B BASE..HEAD`) and checks them against the same sources the implementer follows — the commit rules in the repository's instruction files (AGENTS.md, CLAUDE.md, CONTRIBUTING; reading these is added to the reviewer prompt's `## Read` list) and the brief's Global Constraints. Remedy for a message already committed: the fix pass rewords only the task's own unmerged commits in BASE..HEAD (never a `stack:` merge or anything already on the integration branch), changing messages only, with the tree of each commit unchanged; this is the only rewrite allowed. No trailer is named or banned generically; no other history rewrite; no metadata-lint framework. The report states what is established (Sonnet-tier implementers, no message policy in the Commit step, AGENTS.md not auto-loaded by Claude Code, reviewer rubric and subject-only package) and that which agent produced each commit is inferred, not proven. **Considered:** a commit-msg lint — forbidden; changing the shared `review-package` script to print bodies — discarded, shared with subagent-driven-development, the reviewer instruction suffices; roast judge severity change — not needed, final reviews already graded it correctly.

### 4.8 Validation

Script/test changes are covered by behavior tests in the existing suites (`tests/super-code/test-report-verdict.sh`, `test-dispatch-text.sh`, `test-context-preflight.sh`, `tests/super-auto/test-scripts.sh`, a real-git setup fixture modelled on `tests/super-code/test-setup-cleanup.sh`, prompt-text assertions). Prompt edits to skills are verified by prompt-text assertions plus fixtures rendered from the templates that must parse; full drill pressure evals are run by the orchestrator only where an existing eval already covers the changed behavior (skill-sourced check), otherwise recorded as not run. dryRun agent counts in `coordinator-workflow.md` must not change.

## Key abstractions

**Range relevance rule** — new closure in `reviewInputs` (`dispatch-text.mjs`), built once per invocation from the captured `changed` list and `current`, plus the set of runs re-read as mirror origins, which is complete once `authenticateOrigins` has run at both endpoints; answers whether a `run.md` is in range.
- Owns: the path-only rule of §4.2 — relevant when it is the caller-bound current run, when the run.md or its `.collection-origin.json` sidecar is a changed path, when any changed path is at or under `dirname(run)/reviews/`, or when it is re-read as the origin of a mirror run that is itself relevant by those path criteria.
- Hides: how relevance is decided; `snapshot`, `validateCollections` and `authenticateOrigins` never test paths themselves.
- Must not: read run ids or claims, skip parsing an irrelevant run (the mirror ambiguity check needs every run), or waive a problem.
- Relationships: used only by the run-scoped gap sink.

**Run-scoped gap sink** — new closure in `reviewInputs` replacing run-specific `gap(text)` calls.
- Owns: routing each run-attributed problem to blocking `gaps` or non-blocking `outOfRange`; buffering problems emitted before origin authentication finishes and classifying them once afterward (§4.2 evaluation order). Problems attributable to no run (captured-commit checks, extraction failure, previously claimed payload problems) always go to `gaps`.
- Hides: the two-list split; `snapshotGap`, `collectionGap` and origin-ambiguity calls pass the run and the text only.
- Must not: change `status` or the exit code because of `outOfRange`, or select or omit paths based on it.
- Relationships: depends on the relevance rule; `review-inputs.json` and `generated-input-provenance.md` gain an informational `outOfRange` field and lines.

**`claude_window`** — new bash function in `context-preflight`, a hand-kept mirror of `CLAUDE_WINDOWS` in `context-pass.mjs`.
- Owns: model id → window; case-insensitive `[1m]`; 200K fallback.
- Hides: the table; the explicit-id fallthrough and the same-family alias branch both call it.
- Must not: guess a window for a bare alias without a settings source (stays `unknown`), read env, or apply overrides — env precedence, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and `--context-window` stay outside it.
- Relationships: a parity test runs a matching and a boundary non-matching id per `CLAUDE_WINDOWS` row through both resolvers and checks the two tables have the same row count; cross-reference comments in both files and `MAINTENANCE.md`.

**Bookkeeping completeness checks** — new pass in `scope-dispositions --project`, after the projection is built.
- Owns: the gap `scope-filter decision without finding-route: round <N> <key>` and the additive `unrouted` metric. A declared report with no source is `report-status --acceptance`'s existing source-coverage gap, not this pass's.
- Hides: how run.md fields are read and matched; the key is compared only to detect a missing record.
- Must not: link, route or dispose anything; never treat bead closure, an equal display key or a clean review as resolution.
- Relationships: writes through the existing `gap(origin, message)`, so `FINDING_GAP:` lines and exit 3 cover it.

**`workspaceSetup` (`coordinator.js`)** — extended: the both-exist ordinary-attempt branch gains a drift fragment (ancestry and `stack:` parent check, then rebuilt base and `rebase --onto`, or typed failure); a new fragment covers branch-only and worktree-only on both the ordinary and re-entry paths, running the ALREADY-MERGED CHECK first when the branch exists. The stack-merge command text becomes one local helper used by both the fresh-cut `stackStep` and the drift rebuild. Every failure is `SETUP_FAILED: <cause>` naming the old head or which of branch/worktree exists; the existing mapping to BLOCKED carries it; no new result status.

**`reviewFileFormat()` (`coordinator.js`)** — extended: the single source of the whole-file section rule and the `report-verdict --complete --source format-check` self-check (repair only on exit 4) for final, cluster and seam prompts. The reporter template and the super-roast SKILL.md mirror restate the same rule.

**`report-verdict --complete` and `strictDraft` in `assembly-archive.cjs`** — extended: a sub-heading or bold label inside a recognized section that already has items is an error, by the §4.1(d) sibling/sub-heading discriminator, and a line inside a fenced code block is never a heading; `report-verdict --complete` signals every grammar failure with exit 4, keeping exit 2 for usage and I/O errors. `report-verdict` also gains the `--repair-check ORIGINAL REPAIR` mode (§4.1(c) checks (i)-(iv), exit 0 accept / 4 reject / 2 usage or I/O), owned by the super-roast format-repair leaf and reusing the script's roast section word list.

**`reviewReadiness`** (validated in `super-roast/scripts/assemble-args.mjs`) — extended: fields and meaning documented in the super-roast Inputs table; code-roast derivation stated once in super-auto phase 4 (rounds and post-cap audit); design-roast rule stated once in super-design §Adversarial Review Loop, cited by super-auto's amend design roast.

**Implementer `## Commit` step and task-reviewer severity rules** — extended as prompt text only (§4.7).

Variation: no growing set of kinds. The model-window table grows (one row in `CLAUDE_WINDOWS` and one in `claude_window`; the parity test's per-row ids and row-count check catch a row added to one table alone); the recognized section words are a fixed list held in two copies that change together; readiness values are a closed set `assemble-args.mjs` enforces. No registry or interface is justified.
Walk-through: a product-only change with an old incomplete run elsewhere — the reviewer writes its report per `reviewFileFormat()` and self-checks with `--complete`; `review-inputs` marks the old run irrelevant and the sink sends its gap to `outOfRange`, exit 0; phase 4 derives `complete`/`available` from `review-inputs.json` and passes it; Step 2 records `finding-source` then one `finding-route` per scope decision, and a missing route surfaces as a projection gap. A new 1M Claude model touches one row in each window table.
Per spec §4.1(c): the roast format repair is accepted only by `report-verdict --repair-check` (header block and `--keys` equal, and every non-blank original line kept in order, changed at most by an added `- ` marker or a demoted sub-heading); otherwise the original stays the round's report path. Header-only grammar failures are not re-dispatched.
Per spec §4.1(d): the extractor change lands in both `report-verdict --complete` and `assembly-archive.cjs` `strictDraft`, keeping two grammar copies on purpose; tests run the same sub-heading fixtures against both.
Per spec §4.5: a drift rebase conflict never takes the STACK_CONFLICT `--discard` path; drift failure is always `SETUP_FAILED`.

Digest:
- Range relevance rule: decides whether a run.md is in the captured range using paths and mirror-origin status only (an origin is relevant only through a relevant mirror), evaluated after origin authentication; a new relevance criterion goes in this one predicate; callers never test changed paths or run ids themselves.
- Run-scoped gap sink: routes each run-attributed problem to `gaps` or `outOfRange`, buffering until origins are authenticated; any new per-run validation reports through it; callers never push to `gaps` directly for a run-scoped problem.
- `claude_window`: maps a model id to its window in bash, kept in step with `CLAUDE_WINDOWS` by the parity test; a new model is a row here and in `context-pass.mjs` plus its parity ids; callers never add their own case list of 1M ids.
- Bookkeeping completeness checks: surface a scope-filter decision with no `finding-route` as a projection gap (missing `finding-source` records stay with `report-status`'s source-coverage check); any new missing-record check is added to this pass; callers never use a key match to link or resolve a finding.
