# Review continuity followups — Design

Run: `docs/superpowers/runs/2026-10-28-review-continuity-followups/` · Beads: super-plan-2s3, super-plan-rsc, super-plan-tco, super-plan-row, super-plan-v94, super-plan-1s3, super-plan-zhk

## Goal

The seven open P1/P2 followups from the Herdr mosh Phase 1/2 triage are fixed in the existing scripts, prompts and tests: generated review reports extract completely or fail loudly, review provenance is scoped to the captured range, canonical roast callers carry evidence-backed review readiness, missing finding bookkeeping is visible, reused stacked task workspaces are reconciled with current prerequisites without losing work, both context-window resolvers agree, and project commit policy reaches the commit step and is graded as a requirement.

Literal human request: "lets $ht handoff to claude-2 all p1 and p2 fixes, at once, using /super-auto in fully autonomous mode, both roasts on". Everything below that goes beyond naming the seven issues is this design's elaboration, sourced to each bead's acceptance text.

## 1. Problem description

Two Herdr runs (mosh Phase 1 at alepar/herdr@be183064, Phase 2 at @a900f967) produced seven triaged defects in Superpowers 6.4.2-alepar6.6. Investigation of each (scratchpad findings `inv-*.md`, summarized here) confirmed every code gap: (2s3) `report-verdict --complete` strictly parses every recognized section anywhere in a report, while producer prompts constrain only the closing footer, so narrative `## Findings` sections, prose preambles and sub-headings make extraction fail (exit 2) — and a sub-heading inside a recognized section silently drops the items under it with exit 0; (rsc) `dispatch-text review-inputs` snapshots and validates every `run.md` in the tree at both endpoints, so one untouched old run with an incomplete collection blocks a product-only range; (tco) super-roast requires `reviewReadiness` to converge, but its Inputs table does not list it and no canonical caller passes it, so no canonical roast loop can reach `[converged]`; (row) callers wrote zero `finding-route`/`finding-link`/`finding-disposition` records and nothing detected it — the projection silently returned nothing deferred, and pending human escalations exist only as free-text `parked:` lines; (v94) coordinator workspaceSetup reuses an existing task branch+worktree with no stack step or ancestry check, and has no case at all for branch-only or worktree-only; (1s3) `context-preflight` falls through to 200K for every explicit id that lacks `[1m]`, while `context-pass.mjs`'s documented table gives Opus 5 / Sonnet 5 / Haiku 5.5 / Fable 1M; (zhk) the implementer prompt's Commit step says nothing about message policy, Claude Code loads `CLAUDE.md` not `AGENTS.md`, the harness attribution reminder asks for trailers, and the task-review rubric files a constraint violation under style/Minor while its review package shows commit subjects only.

## 2. Main challenges

Each fix must close the confirmed gap without erasing the guard that caused it: extraction must not start ignoring narrative findings; provenance scoping must not waive inherited gaps that a broad range really contains or filter by run id; readiness must never be synthesized as complete; bookkeeping detection must make omissions visible without inferring resolution from display keys, bead closure or later clean reviews; workspace reconciliation must never reset, delete or WIP-commit task work; the window fix must not invent knowledge for bare aliases; the commit-policy fix must not become a hardcoded trailer ban. Two historical causes stay qualified (exact mosh-hex.5 setup failure; exact commit-producing agent), and the fixes target the verified code gaps only. Skill-text edits must be small and evidence-led (project rule: writing-skills plus behavior evidence), and a separate tab owns super-auto default-flag changes in shared sections.

## 3. Key decisions made

Align producers to the existing extractor grammar and tighten the extractor where it silently loses items, rather than relaxing it. Producers self-check with `report-verdict --complete` and the roast orchestrator re-dispatches the reporter once with the parser error; originals are never overwritten. Provenance relevance is a path-only rule on the captured changed-path inventory. Readiness is derived from the assembler's `review-inputs.json` (code roast) or from committed spec identity (design roast), else `unknown`. Missing bookkeeping becomes explicit projection gaps in the existing `scope-dispositions --project`; pending human escalations use a `finding-route` with a reserved `deferred` reason prefix — no new record kind. Workspace reuse reconciles by rebase of the task's own commits onto a rebuilt stack base only when the worktree is clean, else fails typed with everything preserved. `context-preflight` gets a bash mirror of `CLAUDE_WINDOWS` with a parity test. Commit policy is stated in the implementer's Commit step and graded as Important in task review, with full commit messages in the review evidence.

## 4. Decision points, by section

### 4.1 Report format contract (super-plan-2s3)

**Recommended:** (a) Rewrite `reviewFileFormat()` in `skills/super-code/coordinator.js` (~L2992) to state the whole-file rule: the recognized section words (`findings`, `must fix`, `concerns`, `blockers`, `deferred`, `untested scope`) mark extractable sections anywhere in the file, so narrative analysis goes under headings that do not use those words; each recognized section holds only `- ` items (indented continuation lines allowed) or the single item `- none`; no sub-headings, bold labels or prose preamble inside one. (b) Give every section of the super-roast reporter template (`skills/super-roast/reporter-prompt.md` Step 6 and the mirror in `skills/super-roast/SKILL.md`) the same body rule, including Rejected, Unverified nits and Escalations. (c) Validation: final/cluster/seam reviewers run `report-verdict --complete <their file>` before returning and fix only formatting that it reports (finding content unchanged); the roast orchestrator, after writing `reportMarkdown`, runs `--complete` and on exit 2 re-dispatches the reporter once with the parser error and the original path, writing the repaired report to a new sibling file (`…-format-repair.md`) that becomes the round's report while the original stays on disk and is recorded. (d) Tighten the extractor: in `report-verdict --complete` and the copied grammar in `assembly-archive.cjs`, a sub-heading or bold-label line encountered inside a recognized section that already has items is an error (exit 2), not a section end. **Considered:** relaxing the extractor to accept narrative inside recognized sections — discarded, the issue forbids ignoring narrative findings and it would make keys ambiguous; a mechanical post-dispatch repair with report-status pairing — deferred as a follow-up if self-checks prove unreliable, it needs report-status changes.

### 4.2 Range-scoped review provenance (super-plan-rsc)

**Recommended:** In `reviewInputs()` in `skills/super-code/scripts/dispatch-text.mjs`, compute relevance per `run.md` after the changed-path list: relevant iff it is the caller-bound current run, or the run.md path itself, its `run.md.collection-origin.json` sidecar, or any path at or under `dirname(run)/reviews/` is in the captured changed paths, or it is re-read as a mirror origin (strict as today). Relevant runs keep every existing guard (parse problems, incomplete claimed collections, origin authentication). Irrelevant runs are still parsed (the mirror ambiguity check sees all runs) but their problems go to a new non-blocking `outOfRange` list in `review-inputs.json` and the provenance digest, labelled informational, neither selected nor waived; they never change the exit code. One clause in `skills/super-auto/SKILL.md` §Review collection states the range scoping. A broad range (e.g. a final review from an older upstream base) includes the old run.md as a changed path, so its inherited gaps still block. **Considered:** filter by current run id — discarded, forbidden and wrong for broad ranges; parse claims to decide relevance — discarded, fails on corrupt run.md, while the path rule is a superset of any claim.

### 4.3 Review readiness at canonical callers (super-plan-tco)

**Recommended:** Add a `reviewReadiness` row to super-roast's Inputs table (`skills/super-roast/SKILL.md`) with its fields (`coverage`, `provenance`, `basis`) and its meaning. In super-auto phase 4 (each round and the `post-cap audit`), derive it from the round's assembler result: assembler exit 0 and `<dir>/review-inputs.json` with `status: complete`, no gaps, and base/head equal to the captured SHAs → `complete`/`available` with a basis naming that file, its status and the captured range; the typed `provenance unavailable; captured source available` bounded review → `bounded`/`unavailable` with the cause and inspected/unreviewed scope; any other assembler failure or direct fallback → `unknown`/`unavailable` with the cause. `fits` never changes readiness; readiness is never copied from a prior round nor inferred from a green sweep. Design roasts (super-design §Adversarial Review Loop and super-auto's amend design roast): `complete`/`available` only when every settled spec path is passed and committed clean at a captured HEAD SHA, with the SHA and path list as basis; otherwise `unknown`. **Considered:** always `unknown` for design roasts — discarded, it keeps design loops unable to converge although the artifact is fully captured; coverage-loop pass as basis — discarded, coverage judges the tree, not what the roast read. This design-mode basis is an agent decision and is parked for the human at hand-back.

### 4.4 Finding bookkeeping visibility (super-plan-row)

**Recommended:** In `skills/super-auto/scripts/scope-dispositions --project`, add explicit gaps: `scope-filter decision without finding-route: round <N> <key>` for each recorded `scopeFilter-round-<N>` decision with no `finding-route` on a matching roast occurrence (key used only to detect missing bookkeeping, never to link or resolve), and `declared roast report has no finding-source: <path>` for each `roast-code`/`roast-design` report path lacking a source record; plus an additive `unrouted` metric. Gaps flow through existing exit-3 handling. Instruction fixes in `skills/super-auto/SKILL.md`: Step 2 appends the round's `finding-source` then one `finding-route` per scope decision, and on extraction failure records the gap and never substitutes scope keys for the punch list; Step 3 appends `fix:<bead>` routes; human-gated items (roast Escalations, reserved human decisions) get a `finding-route` with `deferred: "pending human decision: <what>"` carrying the occurrence ref, and the `parked:` line cites that ref; a re-appearance is linked only on a judged basis; resolution only via a `finding-disposition` citing the human's recorded approval line. One sentence in `run-state.md` defines the reserved `pending human decision:` prefix. Bead closure, equal display key or a later clean review never dispose; autonomous mode never writes a human approval. **Considered:** a new escalation record kind — discarded, the existing route `deferred` reason carries it; auto-linking by display key — forbidden.

### 4.5 Reused stacked workspace reconciliation (super-plan-v94)

**Recommended:** Change the workspaceSetup text the coordinator builds (`skills/super-code/coordinator.js` ~L2624-2645, used by both Workflow and ordinary-subagent mode via `dispatch-text.mjs`) so the both-exist ordinary-attempt path first checks drift: some current parent `task-p` is not an ancestor of the task branch (`git merge-base --is-ancestor`), or the branch carries a first-parent `stack: X` commit for an X no longer a current parent. No drift → reuse as today. Drift with a dirty worktree (ignoring `.tmp/`) → `SETUP_FAILED: prerequisite drift; uncommitted work preserved; nothing reset`. Drift with a clean worktree → record old head and old base; on a detached HEAD at the integration branch merge each current parent as `stack: p`, giving the new base; `git rebase --onto <newBase> <oldBase> <branch>`; on any conflict abort, restore the branch to the old head, and return `SETUP_FAILED` naming the old head (never the STACK_CONFLICT `--discard` path). Branch-only or worktree-only states return a typed `SETUP_FAILED` naming which exists, preserving both. No `-D`, `--force`, reset, WIP commit or stash. Docs in `coordinator-workflow.md` and `coordinator-subagents.md` follow. The exact mosh-hex.5 failure cause remains qualified in the report. **Considered:** merging the new parent on top of the task's commits — discarded, it moves base above the task's own commits and the merge-time `rebase --onto` would drop them; resetting the branch to a fresh cut — forbidden.

### 4.6 Consistent model-window resolution (super-plan-1s3)

**Recommended:** Add a bash function `claude_window` to `skills/super-code/scripts/context-preflight` mirroring `CLAUDE_WINDOWS` in `context-pass.mjs` (ERE, case-insensitive `[1m]`), used by the explicit-id fallthrough and the same-family alias branch; keep the bare-alias-without-settings `unknown` case, env precedence, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` and `--context-window` override unchanged; cross-reference comments in both files and `skills/super-code/MAINTENANCE.md`. A parity test runs a list of ids through both resolvers and requires equal windows. **Considered:** calling node from context-preflight — discarded, it is deliberately bash-only; a shared JSON table read by both — more moving parts than a mirrored table guarded by a parity test.

### 4.7 Project commit policy at commit and review (super-plan-zhk)

**Recommended:** In `skills/super-code/implementer-prompt.md` "## Commit", add: commit messages follow the commit rules in the repository's instruction files (AGENTS.md, CLAUDE.md, CONTRIBUTING) and the brief's Global Constraints, and where those conflict with a harness's default attribution or trailer instruction, the project rule wins (fix passes inherit this step). In `skills/super-code/task-reviewer-prompt.md` severity rules, a violation of an explicit project or brief constraint — commit-message policy included — is Important (a missed requirement), not style; the reviewer inspects full commit messages (`git log --format=%B BASE..HEAD`). No trailer is named or banned generically; no history rewrite; no metadata-lint framework. The report states what is established (Sonnet-tier implementers, no message policy in the Commit step, AGENTS.md not auto-loaded by Claude Code, reviewer rubric and subject-only package) and that which agent produced each commit is inferred, not proven. **Considered:** a commit-msg lint — forbidden; changing the shared `review-package` script to print bodies — discarded, shared with subagent-driven-development, the reviewer instruction suffices; roast judge severity change — not needed, final reviews already graded it correctly.

### 4.8 Validation

Script/test changes are covered by behavior tests in the existing suites (`tests/super-code/test-report-verdict.sh`, `test-dispatch-text.sh`, `test-context-preflight.sh`, `tests/super-auto/test-scripts.sh`, a real-git setup fixture modelled on `tests/super-code/test-setup-cleanup.sh`, prompt-text assertions). Prompt edits to skills are verified by prompt-text assertions plus fixtures rendered from the templates that must parse; full drill pressure evals are run by the orchestrator only where an existing eval already covers the changed behavior (skill-sourced check), otherwise recorded as not run. dryRun agent counts in `coordinator-workflow.md` must not change.
