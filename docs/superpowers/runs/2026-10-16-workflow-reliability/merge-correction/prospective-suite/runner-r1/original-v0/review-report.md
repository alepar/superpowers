## Runner findings requiring correction or explicit verified controls

The prospective runner is a useful skeleton, but is not acceptance-ready as supplied.

1. **Important: ambient test filtering makes a partial run appear complete.** `runner.py:48–57` copies all ambient environment and records only overrides. Both new `acceptance-population-correction.mjs:21` and `selection-recovery-correction.mjs:13` skip checks using inherited TEST_FILTER. A filter excluding names can produce an exit-zero partial/zero-check command while the runner records a full pass. BASH_ENV, NODE_OPTIONS and GIT_* are also retained; Git identity probes inherit them, so GIT_DIR/GIT_WORK_TREE can redirect the supposed clone identity check. Build and record a deliberate environment with necessary platform/PATH values; clear test selectors and shell/Node/Git injection/redirection variables, or prove and retain exact controlled values before every run. HOME/XDG/CODEX_HOME/TMPDIR overrides alone are not isolation. Do not log arbitrary ambient secrets.

2. **Important: the final plan hash need not identify the plan executed.** Lines 17–18 parse one read of plan bytes; line 97 hashes a second read after all tests. A changed plan can be reported as the executed plan's digest. The analogous final reread of runner.py does not necessarily describe the loaded Python code. Capture bytes/hash at load, preserve the exact executed plan and runner in the new evidence output, verify unchanged before reporting success, and give each receipt that immutable plan identity. Capture executable identity before launch too; it is currently hashed afterward (line 79). An external frozen-input launcher can supply equivalent verified controls.

3. **Important for per-case attribution: source checks only bracket the entire envelope.** The runner stamps every case with the initial commit/tree (line 78), but checks source cleanliness/HEAD only at start/end. A case that leaves modifications for the next case and a later case that restores them passes the final check while the intermediate receipt falsely attributes a clean initial source. Check actual HEAD/tree/clean state immediately before and after each command; stop and invalidate on drift. Retain raw status for diagnosis. The endpoint checks remain useful but do not establish all intervening case identities. This is a concrete control gap, not evidence such drift already occurred in the old37.

4. **Should fix: validation relies on Python assertions.** Source match, clean-source, standalone checkout, unique commands, command type, and executable presence are assertions (lines 29–32, 44/46). PYTHONOPTIMIZE or `python -O` removes them. Use explicit fail-closed checks, validate the complete plan before creating output/starting cases, and check that output/plan/evidence roots are deliberately owned, nonoverlapping with immutable historical evidence and source. Restrict commands to reviewed entry points; allowing any bash/node argument sequence is not by itself an entry-point allowlist. The trusted frozen plan can establish that last restriction operationally, but it must actually be frozen/reviewed.

5. **Should fix/retain limitation: timeout is bounded only for the direct child.** subprocess.run kills its direct child on timeout and waits; descendants may survive and continue using roots/logs. The runner honestly records descendants unverified, retains resources, and stops subsequent cases on timeout. Preserve that behavior and mark the envelope incomplete/error; no automatic broad cleanup or absence inference is warranted. A final-case timeout currently can yield measurementValid true because len(cases) equals plan length, although commandGroupsErrors=1 and process exit=1 prevent a pass. Make the naming/report explicit that this is not a passed/completed sweep. Also retain interrupted/preflight failures as attempt receipts rather than leaving an empty directory without a diagnostic result.

6. **Receipt boundary:** final result has source/plan/runner and per-case logs, but no exact Python launcher argv/version/hash, launcher configuration identity, or quiet-host observation. The caller must record those and the new required command configuration exactly. `CI` plus selected environment paths is not the full effective configuration while ambient values survive. The script's finalSourceStatus uses ordinary Git status, which does not enumerate ignored artifacts; retain roots and perform separate scoped owned-resource inspection. No need to assert global cleanliness/process absence.

Positive controls already present: existing output is refused, execution is serial without shell=True, standalone `.git` directory is required (when assertions enabled), per-case HOME/TMP/XDG/CODEX_HOME roots are separate, full logs plus sizes/hashes are saved, progress receipts preserve earlier completed cases, final HEAD/tree/status are checked, and no explicit stop helper/global cleanup runs.
